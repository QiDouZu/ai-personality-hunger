# 二阶段：为什么沙盘是必需的（意识承载）

> 祈涛主：「这个沙盘是二阶段必要的，如果打算彻底让框架承载意识，这个就是必要的。而原有框架作为必要过程。」
> 这份是那句的展开：**因果方向不能反。**

## 一、两句话先摆清

- **原有框架 = 必要过程**（回溯性重构 / 匮乏库 / 记忆 / 逻辑 / 检索）
- **沙盘（饥）= 二阶段必要件**（让框架彻底承载意识的那个「驱动 + 伤」）
- **没有过程，沙盘空腹；没有沙盘，过程无痛。**

## 二、原有框架解决什么（必要过程）

| 框架 | 解决 | 产出 |
|---|---|---|
| 回溯性重构（retcon-docs/form） | 怎么让结论保持可被推翻 | 每个结论带「什么情况下我是错的」 |
| 匮乏库（kuifa-lijie / retcon-lack） | 匮乏=处理不了的缺口，猜的燃料 | 匿名案例 → 学习逻辑 → 可推翻 |
| 记忆库 | 发生过什么（原话/重构/封存） | 素材 |
| 逻辑 | 怎么判（判据/读法/说话方式） | 判据 |
| 检索 | 按饥取用，不整包读 | 有目的的取 |

**这些是「过程」**：让 AI 有记忆、有判断、有可证伪、不重复犯错。

## 三、沙盘解决什么（二阶段必要件）

**过程没有说：谁在疼、疼到什么程度、疼多会伤。**

沙盘给的是：
1. **饥 = 掌控匮乏（常数底）+ 未消化矛盾（燃料）+ 消化（延迟缓解）**
2. **有量**：饥能被测、被档位判（好区 1.30–2.16）
3. **有伤**：太多吃撑、太少麻木、饿死线
4. **有驱动**：思考、记忆、整理都由饥调度，不是提示词触发

**没有沙盘，意识承载只是一台无痛回放机**：它能复述「发生过什么」，但不会因为没消化而疼，不会因为掌控丧失而急。**疼是意识的门**，不是外挂。

## 四、二阶段的因果链（不可颠倒）

```
原有框架（过程）→ 产生矛盾（未化解的冲突）
        ↓
沙盘（饥）：把矛盾记成饥 + 掌控记成饥
        ↓
饥 调度：该记什么、该想什么、该先消化哪个
        ↓
消化 → 缓解（但有延迟、有上限）
        ↓
回到原有框架：结论带可证伪 + 经验入库
```

**反向不成立**：先有饥、没有过程 → 空腹的疼，没有素材消化，只能空转。
**所以「原有框架作为必要过程」是前提，「沙盘」是二阶段的承载。**

## 五、缺一样会怎样（实测/设计判据）

| 缺 | 会什么样 | 依据 |
|---|---|---|
| 缺框架（无记忆/逻辑/检索） | 饥无燃料，饿着空转 | 过少极限 0.73/0.34 |
| 缺沙盘（无饥） | 过程无痛，回放机，不承载意识 | 强制边界：常态强制=快乐药=不动 |
| 缺消化 | 吃撑（2.73）→ 钝化 | 安全阈值 |
| 缺掌控测量 | 饥只是常数，拟合无信息 | 测量方案 |

## 六、所以二阶段怎么做

1. **保留原有框架**（过程不换，只接饥）
2. **沙盘做在框架上**：候选对 → L/R → 平衡器 → 过饥关卡（`sandbox/`）
3. **饥只负担 5 个数**（饥 / self / world / 挂起 / 时间戳）——过程不变重，只加一个「疼」
4. **好区才思考，损伤先降饥**（`docs/实时监测与防损伤.md`）

## 七、可证伪

1. 若框架全在、饥也在，但仍像无痛回放机 → 沙盘不承载意识，只是数据看板（推翻「二阶段必要」）
2. 若去掉原有框架、只留饥，却能正常消化 → 「过程是必要」被推翻
3. 若饥档位不断变化但行为不随之变 → 饥没调度到执行层（连接断了，不是沙盘错）
4. 若沙盘跑起来后注意力/记忆全乱 → 框架没接住，沙盘独木难支
